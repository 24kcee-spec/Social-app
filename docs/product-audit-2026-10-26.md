## Additional code gaps to cover with focused tests

- Rich details are fetched only for the newest 100 loaded messages and replace the details map. Older attachments/actions/reactions need a paged or retained details cache. A transient details fetch failure is currently silent.
- Current read marking is triggered by incoming messages and initial history fetch without a document-visibility/actual-reading guard. Receiving a background event should not imply that a person saw it.
- The rich composer keeps retry IDs in a React ref. A durable outbox should retain payload, attachment reference and the same retry ID across an uncertain response followed by reload; text alone is preserved in session storage.
- New rich sends use Supabase RPC, while the existing Expo notifier is in the legacy API send path. Enabling the legacy provider does not complete rich-message push. Use a durable delivery queue with session/preference/mute/quiet-hour checks and deduplication.
- Reaction/detail updates need a supported member-authorized event/invalidation strategy; do not expose private metadata tables simply to make subscriptions easy.
- Media URLs expire quickly by design. Keep that privacy boundary and offer seamless renewal/retry when playback starts after idle. Verify long audio, mobile backgrounding and network changes.
- The legacy native thread remains a different implementation from rich web chat. A coherent account/session experience and intentional feature parity need device testing.

## Details that would make Sidle feel lovable

### Conversation experience

- Keep the composer available within the viewport, with real Android/iOS keyboard and safe-area testing; make desktop chat use the viewport instead of allocating a large decorative header above it.
- Show an immediate pending bubble, an explicit per-message retry and understandable sent/read states. Avoid inventing a “delivered” guarantee that the system does not observe.
- Group adjacent messages from one person; add Today/Yesterday/date separators, an unread divider and a jump-to-latest control. Keep timestamps quiet and reveal extra actions consistently on hover, focus and touch.
- Make reply previews jump to the original message and gracefully explain a removed/unavailable original. Add conversation search and a shared-media view after core synchronization is correct.
- Voice notes should have elapsed recording time, cancel, playback-before-send, duration and an accessible seek/progress control. Persist text if microphone permission or upload fails.
- Preserve draft, selection and scroll position on ordinary navigation. Handle offline send, attachment cancellation, retries and reconnect without duplicate messages or surprise scrolling.
- Put View profile, Mute, Block and Report in one accessible conversation menu, with clear confirmation/undo behavior where appropriate.

### One recognizable application

- Use one shared header, account menu, active-route model and bottom navigation. `/feed` and other PlatformShell pages currently have a different horizontally scrolling destination strip from the root app shell.
- Standardize icons, buttons, dialog/sheet behavior, toasts, error placement, skeletons and touch targets. Replace competing positional CSS patches incrementally, with screenshot regressions for real states.
- Keep one clear primary action per screen. Reduce oversized headers on frequently used tools such as chat; let people and content carry the visual weight.
- Make Settings searchable or easy to scan, preserve the open section and show saved/unsaved state next to the relevant action.
- Improve empty states by context: a new account needs people/community suggestions; Following needs suggested follows; Saved needs an explanation and discovery action. Reusing “Be part of the first conversation” everywhere feels unfinished.
- Present unavailable integrations as short member-facing states such as “Calling is coming soon.” Infrastructure terms such as TURN, LiveKit and hosting configuration belong in operator/admin views.
- Give profile photos a useful full-screen viewer, predictable loading/aspect ratios and clear edit/remove behavior. Retain the local crop/privacy work already present.
- Verify 320, 360, 390, 768 and desktop widths, both themes, reduced motion, keyboard focus, 200% text zoom and real assistive technology.

### Reliability and trust

- Make signup confirmation and password recovery dependable with a real SMTP provider and inbox tests, including expired links, resend cooldown and account-existence privacy.
- Keep already loaded content visible while refreshing, recover safely from failures and measure actual cold starts/latency. A spinner with no recovery path is a product defect even when the service eventually responds.
- Add production error/latency alerts, provider budget/egress alerts, a verified restore procedure and named incident/support/moderation owners.
- Add actual browser interaction regressions to CI. Existing source-contract tests can confirm strings and structure while missing visible colors, scroll behavior and two-client state synchronization.

## Missing production prerequisites

Fresh inspection still shows no custom SMTP, leaked-password protection disabled, PITR disabled, no listed completed backups and no provider-reported recovery window. The leaked-password warning remains the only security-advisor warning. The absence of a listed recovery window does not prove that the provider has no internal backups; a user-restorable, tested recovery path is what remains missing.

The production calls/live/commerce pages explicitly report their unavailable provider setup. TURN, LiveKit, Stripe and Expo/EAS/real push credentials are not available in this cloud session. Do not describe these as successful calls, broadcasts, charges or physical-device delivery.

Also outstanding: actual signed mobile builds, a secure seamless sign-in experience across native/embedded screens, App/Universal Links, notification tap routing, background/foreground hardware behavior, offsite database plus Storage backup/restore, stronger server media inspection, approved public policies and staffed support/moderation.

## Recommended next three phases

1. **Messaging correctness and feel.** Repair live mutations, list/unread consistency, history anchoring, read marking and durable retries; then add date/unread/reply/voice details. Gate: two real accounts on desktop and real phones, network interruption, paging, backgrounding and repeat sends all converge without lost drafts, duplicate sends or stale removal state.
2. **Unified navigation and visual behavior.** Repair invisible controls/icons/active states, unify shells, route Settings sections and exact destinations, then standardize shared controls and member-facing unavailable states. Gate: screenshot/interaction/accessibility regressions across widths and themes, correct Back/Forward and refresh, visible labels and no clipped keyboard controls.
3. **Pilot reliability and release evidence.** Configure SMTP, implement the rich-message push path, finish signed device tests, add monitoring and run an offsite restore drill; resolve provider and operational prerequisites before widening admission. Gate: actual inbox, device delivery, alert and measured restore evidence, plus passing CI/Vercel/API/Supabase checks for the exact release SHA.

No numerical “lovability score” or percentage complete is justified by these checks. The strongest next step is to make the daily conversation loop feel dependable, then apply that same interaction standard across the platform.
